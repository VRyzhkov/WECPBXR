# Конспект разработки WECPBXR

Этот файл - рабочий конспект проекта. Здесь фиксируются архитектурные решения, состояние разработки, важные ограничения, проверки и заметки для следующих итераций.

## Назначение проекта

WECPBXR - кроссплатформенное desktop-приложение для управления микшерами Behringer XR по Ethernet через MIDI-контроллер Miwayer Worlde Easycontrol Plus. Приложение принимает MIDI-события, сопоставляет их с назначениями в карте и отправляет OSC-команды микшеру.

Ключевой сценарий: живое управление уровнем, mute, pan, bus/aux/fx send и служебными командами микшера с физического MIDI-контроллера, с визуальной обратной связью и редактируемой картой назначений.

## Структура решения

- `WECPBXR.UI` - Avalonia desktop UI, пользовательские настройки, визуальное состояние контролов, режимы assign/learn.
- `WECPBXR.Console` - диагностическая консоль для проверки MIDI/OSC, сканирования микшеров, редактирования и симуляции карты.
- `WECPBXR.Core` - доменные модели, банки, движок маппинга, загрузка/сохранение MIDI-карты, каталог команд микшера, soft takeover.
- `WECPBXR.Hardware` - MIDI input через DryWetMidi, OSC-клиент микшера, сетевой сканер XR-устройств.

## Технологии и зависимости

- .NET 8.
- Avalonia 12.1.1 для desktop UI.
- `Melanchall.DryWetMidi` для MIDI-входа.
- `Rug.Osc` для OSC-сообщений.
- UDP-порт XR/X-Air микшеров: `10024`.

## Текущая карта функциональности

- UI повторяет поверхность Easycontrol Plus: 24 энкодера, 9 фейдеров, 20 назначаемых кнопок.
- Поддерживаются программные банки с отдельными названиями, цветами, подписями и назначениями.
- Есть режим назначения mixer binding в UI.
- Есть MIDI learn для назначения физического контроллера на выбранный программный слот.
- Непрерывные контролы используют soft takeover: значение начинает отправляться только после догоняния текущего значения микшера.
- Кнопки используют toggle-by-press для сценариев вроде mute.
- Карта назначений хранится в `WECPBXR.Console/midi-map.json` и копируется в output UI как `midi-map.json`.

## Важные ограничения

- Проект находится в beta-состоянии и требует проверки с реальным MIDI-контроллером и XR-микшером.
- Протокол физической RGB-обратной связи Easycontrol Plus пока не подтвержден.
- FX send OSC-индексы основаны на ожидаемой XR/X-Air схеме и требуют проверки на железе.
- Сканер ищет устройства только в локальных IPv4 `/24` подсетях.
- `Rug.Osc` восстанавливается как .NET Framework package и может давать NuGet compatibility warnings, хотя сборка проходит.

## Решения

### Карта назначений живет в консольном проекте

Базовая карта хранится в `WECPBXR.Console/midi-map.json`, а UI подключает ее как linked content и копирует в выходную директорию. Это позволяет использовать один исходный map-файл и для диагностической консоли, и для desktop-приложения.

### Core не зависит от UI и Hardware

Логика банков, маппинга, конфигурации и каталог mixer-команд находится в `WECPBXR.Core`. UI и Hardware используют Core, но Core не должен знать о Avalonia, MIDI-устройствах или сетевом транспорте.

### Hardware изолирует внешние протоколы

Работа с MIDI, OSC и сетевым поиском вынесена в `WECPBXR.Hardware`, чтобы доменная логика могла тестироваться и развиваться без прямой привязки к устройствам.
